# AntiScam v0.7 — короткий ответ об угрозах, содержимое ссылок и проверка файлов

Публичный экспериментальный сайт на **FastAPI + HTML/CSS/JavaScript**. Имеет локальный анализ адресов, интеграцию с Google Safe Browsing v5 и VirusTotal и безопасный статический анализ загруженных файлов. Дизайн и страницы `/`, `/file`, `/about` сохранены.

## Новое в v0.7 — короткий ответ «Есть ли вирус?»

После каждой проверки ссылки и файла в начале результата появилась выделенная секция с четырьмя возможными ответами:

1. **Есть известная угроза** — есть положительные результаты в базах. Для URL это может быть не вирус, а фишинг.
2. **Возможно опасно** — найдены эвристические признаки или подозрительные результаты, но вирус не подтверждён.
3. **Известных угроз не обнаружено** — доступные проверки не показали известных опасностей. Это **не значит**, что вирусов гарантированно нет.
4. **Определить не удалось** — недостаточно результатов внешних баз и/или нет достоверного анализа содержимого.

Ответ вычисляется на сервере из уже имеющихся результатов проверки, а JavaScript отображает его на странице. JavaScript не умеет достоверно обнаруживать неизвестные вирусы и не выполняет сторонние скрипты. Для действительно нового вредоносного ПО потребуются отдельный антивирусный движок, защищённая песочница и многоуровневый аудит безопасности. Никакой анализатор не может гарантировать 100% отсутствие угроз.

Обновление v0.7 **не требует новых API-ключей или зависимостей**; `requirements.txt` остаётся прежним.

## Новое в v0.6 — статический просмотр содержимого ссылки

По **отдельному явному согласию** посетителя функция «Посмотреть содержимое страницы (бета)» выполняет безопасно ограниченный HTTP GET и анализирует **не более первых 128 КиБ ответа**. Показывает:

- Конечный домен после не более 3 контролируемых HTTP-перенаправлений; внутренние и служебные IP-адреса блокируются, включая DNS rebinding.
- Заголовок HTML-страницы, наличие форм паролей, потенциально подозрительные действия форм, скрытые iframe, meta refresh и ссылки на исполняемые файлы.
- Реальный формат по первым байтам для PDF, ZIP, EXE/PE, ELF, PNG, JPEG; формат по Content-Type для HTML/JSON/XML; несовпадение сигнатуры EXE и Content-Type отмечается как высокий риск.
- Причины сомнений в результатах и отдельные ограничения проверки.

**Никакого запуска JavaScript, полноценной загрузки архивов, скачивания вложенных ресурсов, входа в аккаунты, cookies, выполнения HTML или антивирусного движка.** Для страниц, зависящих от JavaScript, может быть невозможно узнать реальный вид браузерной страницы. Изолированное динамическое сканирование браузером и полноценный антивирус не входят в v0.6.

На публичном Render URL-превью использует соединение только с публичными IP, проверку каждого перенаправления, запрет нестандартных портов, отключённое следование редиректам, запрет прокси, сетевой тайм-аут и лимит одновременно работающих GET. Но **это экспериментальная функция: перед массовым запуском нужен независимый аудит SSRF-защиты, тестирование и инфраструктурные лимиты**. Обычный сервер Render не является песочницей для исполнения чужих скриптов.

Если пользователь не поставит галочку, никакая загрузка страницы не происходит. Не проверяйте приватные URL или ссылки с токенами, потому что сайт назначения увидит посещение AntiScam; приватные данные не следует отправлять внешним репутационным сервисам.

## Сохранено из v0.5 — собственный анализ адреса

- **Без внешней базы** анализирует текст URL: возможная имитация популярных сервисов, смешение алфавитов, Punycode, сокращатели, небезопасный HTTP, расширения исполняемых файлов, двойные расширения и URL с подозрительными перенаправлениями.
- Самостоятельная проверка URL не открывает адрес и не запускает содержимое. Режим чтения страницы включается отдельной галочкой. Google и VirusTotal также подключаются только по согласию.
- В результатах появился блок **«Собственный анализ AntiScam v0.5»** с объяснениями и ограничениями метода. Результаты внешних баз продолжают показываться отдельно.
- Когда база ничего не знает о ссылке, подозрительные признаки всё равно могут дать **«Требуется осторожность»**, но отсутствие признаков не превращается в зелёное «безопасно».
- Ложные срабатывания возможны. Наличие признаков **не доказывает**, что сайт фишинговый или содержит вирусы; отсутствие признаков **не доказывает**, что он безопасен.

Никакого ИИ-обучения или полноценного антивирусного сканирования здесь нет: версия 0.5 использует прозрачные ограниченные правила (эвристики). Полноценное динамическое исследование неизвестных сайтов и новых вредоносов требует отдельной изолированной инфраструктуры, не обычного сервера Render.

## Сохранилось из v0.4 — проверка файлов


- Определение действительного типа файла по сигнатуре и структуре ZIP/Office-контейнера.
- Обзор **имён** первых десяти элементов обычного ZIP; для Office показываются только важные вложения. Ни один элемент не распаковывается на диск и не исполняется.
- Предупреждения о двойных расширениях, вложенных программах и архивах, чрезмерном размере распаковки, зашифрованных элементах, небезопасных путях и символьных ссылках ZIP.
- Поиск видимых признаков макросов VBA, встроенных объектов и внешних связей в OOXML-документах; характерных конструкций активного содержимого/вложений/шифрования в PDF; активного содержимого в HTML и SVG.
- В интерфейсе появился отдельный блок **«Что проверил AntiScam»** и обзор содержимого ZIP.
- Возможность сверить **SHA-256** с уже существующим отчётом VirusTotal **по согласию пользователя**. Сам файл **не передаётся** VirusTotal; если хеш неизвестен, результат остаётся неопределённым.

## Ограничения

**Это не антивирусный движок.** Система не запускает и не сканирует байты сигнатурами полноценного антивируса. Определение типа, обнаружение активного содержимого и поиск репутации по хешу не гарантируют безопасность. Признаки могут быть как у безопасных документов, так и у вредоносных; ложные срабатывания возможны.

- Не скачивайте подозрительные файлы только ради загрузки в AntiScam. Начните с проверки подозрительной ссылки.
- Файлы ограничены 8 МиБ. Приложение не сохраняет их постоянно, но инфраструктура загрузки может использовать временные буферы или файлы; на публичных серверах не загружайте конфиденциальные документы.
- Для RAR/7z внутренние имена не раскрываются. ZIP и Office проверяются **по метаданным**, без полного анализа вложений. PDF/HTML/SVG проверяются **по отдельным эвристическим признакам**.
- VirusTotal получает SHA-256 только с согласия. Даже хеш может быть конфиденциальным идентификатором файла и попасть в базы/логи внешнего сервиса. Нет гарантии нового сканирования неизвестных файлов.
- На публичном прототипе ограничение запросов действует лишь в пределах **одного процесса**; требуется WAF, распределённый rate limit, изоляция загрузок и аудит безопасности перед массовым запуском.

## Как обновить уже опубликованный AntiScam через GitHub

1. Скачайте ZIP **AntiScam_v0.6_обновление_GitHub.zip**.
2. Распакуйте на компьютер и откройте свой репозиторий, например `https://github.com/AlexanderHedlund-prog/AntiScam`.
3. Нажмите **Add file → Upload files**. Перетащите **содержимое** распакованного архива из его корня. Важные файлы должны лежать как `app/page_inspector.py`, `app/scanner.py`, `app/main.py`, `app/static/...`, `tests/...`, а `README.md` — в корне репозитория. Не создавайте лишнюю вложенную папку `AntiScam`.
4. Подтвердите замену старых файлов и нажмите **Commit changes**.
5. На Render дождитесь автоматического deploy до состояния **Live**. Если авторазвёртывание отключено, вручную выберите **Deploy latest commit**.
6. Убедитесь, что `https://antiscam-xj4u.onrender.com/health` возвращает `version: 0.6.0`. Затем на главной странице попробуйте `https://example.com` с галочкой «Посмотреть содержимое страницы (бета)» и убедитесь, что появился новый блок «Куда ведёт ссылка». Публичный сайт может блокировать автоматические запросы, поэтому успешное получение содержимого не гарантировано. Можно проверить синтетический пример `https://paypal-login.example.net/` (этот адрес **не следует открывать**; это только текстовый тест).

**Не нужно** создавать новый сервис Render и **не нужно** переносить API-ключи из `Render → Environment` в GitHub: они уже останутся в Render после обновления.

## Локальный запуск

Требуется Python 3.11+.

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux / macOS: source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Пути: `/` — проверка ссылок; `/file` — файлы; `/about` — о проекте; `/health` — версия и состояние; `/api/providers` — только признак наличия ключей.

## API-ключи

Настраиваются **только через Render → Environment** или локальный `.env` (он игнорируется в Git). Ключи никогда не публикуются и не отправляются пользователю:

```dotenv
VIRUSTOTAL_API_KEY=
GOOGLE_SAFE_BROWSING_API_KEY=
RATE_LIMIT_PER_MINUTE=12
```

Внешние проверки Google Safe Browsing v5 и VirusTotal сохранены. Ключи в Render не меняются. Бесплатные ключи имеют ограничения и условия некоммерческого использования. Само размещение кода на GitHub не обновляет сайт, пока Render не завершит развёртывание.
